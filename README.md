# flipper_stealth

Flipper Zero app that displays (fake) medical information, as a stealth/prop
screen. It looks like a bedside patient monitor: heart rate with a live trend
graph on the left, non-invasive cuff blood pressure on the right.

**Nothing here measures anything.** The Flipper has no heart-rate or blood
pressure sensor. Every number on screen is generated by a random walk in
software. It's a prop - don't put it in front of anyone who might take it for
a real reading.

## The screen

```text
 HR                    bpm │      NIBP
                           │
          78               │       118        <- systolic
                           │       /76        <- diastolic
 ┌───────────────────────┐ │       mmHg
 │        ╱╲    ╱╲       │ │
 │   ╱╲__╱  ╲__╱  ╲_╱▪   │ │      MAP 90
 └───────────────────────┘ │
```

- **Heart rate** (left): the current value in large digits, over a trend graph
  of the last 78 readings. The graph scrolls left once it fills, and the newest
  sample is marked.
- **Blood pressure** (right): systolic over diastolic, plus the mean arterial
  pressure a real monitor derives from them.

Press **Back** to exit.

## How the numbers behave

Every update cycle - a fresh random 1000-2000 ms each time, so the refresh
doesn't tick like a metronome - each reading moves **1 to 4 units up or down**,
direction chosen at random.

Values random-walk inside plausible resting-adult ranges (`src/vitals.h`):

| Reading    | Range        |
| ---------- | ------------ |
| Heart rate | 58-96 bpm    |
| Systolic   | 105-132 mmHg |
| Diastolic  | 66-86 mmHg   |

A step that would leave a range turns around and walks the same distance the
other way instead, so a reading never repeats unchanged and never parks on a
boundary - both of which make a fake display obvious. Systolic and diastolic
walk independently, then the diastolic is nudged until the gap between them
(the pulse pressure) lands in a clinically plausible 32-56 mmHg, so you never
get a nonsense pairing like 106/86.

## Build and install

```sh
make setup            # install ufbt + pull the Flipper SDK (once)
make build            # build the .fap
make install SD=E:    # copy it onto an SD card mounted at E:
make launch           # or: build + launch on a USB-connected Flipper
```

`make help` lists everything. Note that `ufbt build` doesn't leave the `.fap`
in this directory - it builds into `~/.ufbt/build/stealth.fap`, a per-user
cache shared across every ufbt app you build. `make install` and `make launch`
know where to find it.

On the Flipper the app appears under **Apps → Games → Stealth**.

## Releases

Pushing a branch named `rel-*` (e.g. `rel-1.0.0`) triggers
`.github/workflows/release.yml`, which builds the `.fap` and publishes or
updates a GitHub Release named after the branch with the `.fap` attached.
`workflow_dispatch` lets you re-release a `rel-*` branch without an empty
commit.

## Layout of the source

| File                  | What's in it                                                         |
| --------------------- | -------------------------------------------------------------------- |
| `src/stealth.c`       | App entry point, setup/teardown, and the deadline-driven update loop |
| `src/stealth_i.h`     | The app struct shared between the loop and the draw callback         |
| `src/vitals.c` / `.h` | The simulated readings: ranges, the random walk, trend history       |
| `src/monitor_draw.c`  | Everything that puts pixels on the 128x64 screen                     |
